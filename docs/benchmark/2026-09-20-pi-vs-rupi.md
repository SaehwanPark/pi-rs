# Benchmark report: `rupi` vs `pi`

Status: WIP — cases 01–05 measured; cases 06–10 pending.

This report records a fresh-memory comparison of `rupi` and Pi 0.86.1 on the ten
repository evaluation cases under [`cases/`](../../cases/). The fixed inference
server is llama.cpp serving Qwen 3.8 Flash Next (UD-IQ4_XS).

The quantitative result tables and raw run evidence are generated under the ignored
`.benchmark/` directory. The checked-in harness is
[`bench/compare-pi-rupi.ps1`](../../bench/compare-pi-rupi.ps1).

## Executive summary

The first five cases completed for both agents under the fixed protocol, with zero
of ten agent/case runs reaching the independent acceptance oracle within two turns.
This is an interim result, not the final ten-case verdict. Rupi consumed more
measured provider input context in every completed case, while Pi produced more
output in the two cases where it began writing a substantive package. Both agents
usually spent the full 300-second turn budget; Rupi exited early with a process
failure on cases 04 and 05 after tool activity, and Pi timed out on all five cases.

## Research questions

1. How many agent turns are required before the independent acceptance oracle passes?
2. How many provider input/output tokens are consumed?
3. How much wall-clock time elapses in agent execution and through independent
   resolution verification?
4. How do the agents differ in tool use, recovery behavior, intermediate quality,
   and final artifacts?

## Fixed protocol

- Model: `qwen3.8-flash-next` from llama.cpp at `http://127.0.0.1:8000/v1`.
- We use the requested server command line, including 262,144 context, 32,768
  maximum generation, IQ4_XS weights, xhigh server reasoning, temperature `1.0`,
  top-p `0.95`, top-k `20`, q8 KV cache, and flash attention.
- Each case starts from a clean scratch workspace containing only its specification,
  configuration files, and ignore rules. Existing implementations and prior case
  reports are not copied into the agent workspace.
- Each agent receives the same neutral implementation prompt and at most one
  standardized recovery prompt. A turn is one CLI invocation/user request; internal
  provider requests are counted separately.
- The client-side benchmark policy is also fixed: thinking level `low`, a maximum
  of 8 model requests per Rupi turn, and a maximum output budget of 16,384 tokens
  for both clients. These settings are normalization choices for the comparison;
  the llama.cpp server command remains the requested one.
- A case is resolved only when the unchanged, fresh-process acceptance oracle exits
  zero. Agent prose and self-reported test results are not acceptance evidence.
- Raw stdout, stderr, traces/session logs, generated files, verification output, and
  machine-readable summaries remain in `.benchmark/` and are ignored by Git.

### Qualitative comparison

In the first segment, Pi made more visible source-file progress on cases 03 and 04:
it left four package files on case 03 and two on case 04, while Rupi left no package
files on case 03 and only the package initializer on case 04. This is an outcome
observation, not an acceptance claim: all ten workspaces still failed their project
tests and independent oracle checks. Rupi’s traces show repeated `read`/`exec`
activity and much larger input totals; Pi’s traces show shorter context totals but
more `write`/`edit` activity once it began implementing. Tool names are descriptive
only; the raw traces and generated-file snapshots are the evidence.

## Per-case observations

Interim observations from run `bench-20260920-01-05`:

- 01 Task Ledger: neither agent created project files beyond the supplied baseline;
  both consumed two turns and failed the oracle.
- 02 Reading Queue: neither agent created project files beyond the supplied
  baseline; Rupi used more input tokens, while both remained unresolved.
- 03 Event Outbox: Pi created `outbox/__init__.py`, `db.py`, `jsonio.py`, and
  `validation.py`; Rupi created no package files. Neither passed tests or oracle.
- 04 Webhook Inbox: Rupi created only `webhookinbox/__init__.py`; Pi also created
  `errors.py`. Rupi’s process exited non-zero before the 300-second cap on both
  turns; Pi timed out on both. Neither passed the oracle.
- 05 Batch Relay: neither agent created package files. Rupi’s two turns exited
  non-zero after tool activity; Pi timed out on both turns. Neither passed the
  oracle.

## Limitations and interpretation

The first segment is censored by the two-turn and 300-second-per-turn limits: an
unresolved run is not evidence that the implementation would never converge. The
model uses temperature `1.0`, so this is one stochastic sample per agent/case, not
an estimate of a distribution. Pi 0.86.1 and the current Rupi binary are compared
as user-facing runtimes, so wrapper and tool-surface differences are part of the
observed behavior. The clients share the model endpoint and key generation
parameters, but their prompt/session formats and tool adapters are not identical.
Verification commands run independently after each turn; acceptance is based only
on the unchanged oracle exit code.

`.benchmark/`. It does not modify the checked-in case projects.

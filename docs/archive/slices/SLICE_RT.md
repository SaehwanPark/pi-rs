# Slice: every AgentEvent variant survives store round-trip

`docs/EVENT_VARIANTS.txt` lists the 22 `AgentEvent` variants, generated by:
`awk '/pub enum AgentEvent/,/^}/' crates/pi-rs-core/src/event.rs | grep -oE '^  [A-Z][A-Za-z0-9]*'`

**Task:** for each variant, a store round-trip test — construct it, append it through the store, restore,
assert it comes back as the same variant with the identifying fields intact. Table-driven if the store API
allows; otherwise grouped tests. **A variant that cannot round-trip is the finding**: give it its own test,
assert the observed behaviour (dropped, rejected, or lossily restored), and name it after what actually
happens. Do not delete or skip cases to make the suite green, and do not change production code.

Evidence rule: every path, line, and API name you report comes from command output in the same message; if
a grep is empty write `not found`; if the store API doesn't exist as expected, stop and report rather than
inventing it.

Limits: `read` with offset/limit ≤40 lines; `grep -n ... | head -20`; command output ≤20 lines; commit
every 4–6 variants (4–5 commits). `cargo test -p pi-rs-store` while iterating; `--workspace` once at the
end. No ROADMAP tick. No merges/rebases/pushes/PRs; stay in this worktree; `git rev-parse HEAD` before
each commit — stop and report if it moved without your commit.

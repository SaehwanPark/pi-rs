# Audit 006 — durable redaction boundary

- **Date:** 2026-09-16 UTC
- **Base:** `main` / `origin/main` at `c57f330` (PR #88 merge)
- **Working branch:** `loop/20260915-improvement-006`
- **Roadmap slice:** ongoing Security — maintain redaction tests and audit raw-payload handling.

## Scope and method

This is a local adversarial review of the durable store boundary, focused on every path in
`pi-rs-store` that writes model-, provider-, or user-supplied text outside the normalized
trace line: raw provider payloads, reduced/recovery blobs, and checkpoint capsules. The review
compares `crates/pi-rs-store/src/{store,journal,session_log}.rs` and
`crates/pi-rs-core/src/redact.rs` with the redaction requirements in `ARCHITECTURE.md` §20,
the canonical design's security section, and the store tests. No external adviser findings
are claimed.

returned `Authentication required`, so 5-hour and weekly percentages are unknown. No
model-backed child was started; the loop remains single-agent and will preserve/push state

### R-1 — opt-in raw capture bypasses redaction

**Evidence:** `crates/pi-rs-store/src/store.rs:401-420` checks that raw capture is enabled and
then calls `self.blobs.put(raw, None)` at line 409. `BlobStore::put` is intentionally a
low-level byte writer and does not own a `RedactionPolicy`. The raw bytes therefore reach the
session blob directory unchanged. The existing test at `store.rs:994-1043` proves only that
the pointer is opt-in and out-of-line; its expected captured object is the original
`{"api_key":"secret-value"}`.

**Failure scenario:** A provider wire response containing a credential is captured for
diagnosis. Enabling raw capture is an explicit choice to retain the wire format, not a choice
to disable the repository's redaction boundary. The `raw_ref` makes the unredacted blob
recoverable from the durable trace.

**Invariant:** `ARCHITECTURE.md:670-672` requires all durable trace output to pass through the
redaction policy and makes raw capture opt-in; the canonical trace/storage rule also says
redaction runs before bytes leave the line. Opt-in capture must preserve that invariant.

**Recommended correction:** Redact raw bytes at the `Session` boundary before `BlobStore::put`.
When the bytes decode as JSON, use `apply_json` so credential-bearing keys are replaced
wholesale; otherwise apply the existing text policy. Preserve the redacted logical bytes in
the content-addressed reference and test that neither the line nor the blob contains the
credential.

### R-2 — recovery blob paths only perform text scanning

**Evidence:** `crates/pi-rs-store/src/store.rs:535-550` calls
`RedactionPolicy::apply` on `String::from_utf8_lossy(bytes)` for both `put_payload` and
`put_recovery_blob`. `RedactionPolicy::apply_json` is the only method that recognizes
credential-bearing keys (`crates/pi-rs-core/src/redact.rs:173-216`), but it is not used here.
A recovery payload such as `{"api_key":"plain-secret"}` therefore remains unchanged when
it is not also a configured literal, environment value, or recognized key-prefix token.

**Failure scenario:** An oversized tool result or compaction summary is JSON containing a
credential under `api_key`, `token`, or a provider-specific `*_secret` key. The runtime stores
the recovery blob before emitting the reduced event, so the event line can be redacted while
the blob retains the secret that the recovery reference exposes.

**Invariant:** The store module documents that redaction is enforced at the durable boundary,
and `RedactionPolicy::apply_json` explicitly promises wholesale treatment of credential
fields. All durable blob payloads need the same structured handling as durable lines.

**Recommended correction:** Centralize byte redaction for all `Session`-owned payload writes;
retain original bytes only when no replacement is required, and serialize a changed JSON value
back to sanitized bytes. Add tests for both inline/blob threshold paths and recovery blobs.

### R-3 — checkpoint archive is written outside the redaction boundary

**Evidence:** `crates/pi-rs-store/src/store.rs:484-505` serializes `capsule` directly with
`serde_json::to_vec_pretty` and writes it with `std::fs::write` at line 494. The later
`SessionLog::append` call sanitizes the duplicated barrier record through
`session_log.rs:216-222`, but the standalone file read by `Session::list_checkpoints` is the
file written before that sanitization.

**Failure scenario:** A capsule objective, decision rationale, constraint, artifact note, or
unresolved item contains a provider key or a configured project secret. The session barrier
may be sanitized while `checkpoints/<id>.json` retains the original value and remains a
first-class durable artifact.

**Invariant:** `ARCHITECTURE.md:670` applies to all durable trace/state output, and checkpoint
archives are explicitly durable state (`ARCHITECTURE.md:376`, `ROADMAP.md:402`). A standalone
checkpoint must not be less protected than its duplicated barrier.

**Recommended correction:** Convert the capsule to JSON, apply the configured structured
redaction policy, and write the sanitized value atomically. Verify the on-disk capsule and
restored barrier contain the marker rather than the secret.

## Clean checks and explicit exclusions

- **Clean:** `TraceJournal::append_bounded` serializes the entry and invokes
  `policy.apply_json` before payload bounding (`crates/pi-rs-store/src/journal.rs:130-159`),
  so normalized event fields and spilled event values use the intended ordering.
- **Clean:** `SessionLog::sanitize_record` applies `apply_json` before every session record is
  serialized (`crates/pi-rs-store/src/session_log.rs:216-222`).
- **Clean:** `RawPayloadCapture` defaults to `Disabled`; this limits exposure by default but
  does not resolve R-1 when diagnosis explicitly enables capture.
- **Not findings in this slice:** file permissions, project trust, and extension/MCP
  subprocess boundaries were not re-audited here. They remain explicit roadmap items for
  later bounded loops and are not being marked complete or silently deferred as resolved.

## Remediation evidence (2026-09-16 UTC)

Commit `e671a1f` implements the accepted disposition:

- `Session::emit_with_payload`, `put_payload`, and `put_recovery_blob` now share a durable
  payload helper that applies structured JSON redaction, falls back to text scanning, and
  preserves unchanged binary bytes.
- `Session::checkpoint` applies `RedactionPolicy::apply_json` before the standalone capsule is
  atomically renamed into `checkpoints/<id>.json`.
- Regression tests cover opt-in raw capture, inline and oversized structured credentials,
  recovery blobs, binary preservation, and both standalone/restored checkpoint representations.

# Provider Context-Overflow Recovery — Implementation Plan

## 1. Objective

Implement a clean replacement for the experimental `feat/auto-summarize-on-overflow` branch.

The runtime should recover automatically when a provider rejects a model request with `ContextOverflow`, but only when recovery is demonstrably safe:

1. The provider has committed no reasoning, text, or tool-call content.
2. There is pre-turn history available to compact.
3. Recovery has not already been attempted during the current user turn.
4. The compacted replacement request can plausibly fit the active provider's context window.
5. The runtime preserves all context created during the current turn.

The implementation must reuse the compaction/event infrastructure already present on current `main` rather than porting the WIP branch's parallel maintenance system.

After the replacement implementation is merged:

* delete `feat/auto-summarize-on-overflow`;
* close Issue #76 as superseded/resolved by the replacement PR;
* retain any generally useful lessons from the WIP in tests or documentation.

---

# 2. Scope

## In scope

Implement:

* provider-reported `ContextOverflow` interception;
* one automatic recovery attempt per user turn;
* strict no-retry-after-commit semantics;
* pre-turn-prefix-only compaction;
* exact candidate request construction using normal request assembly;
* UTF-8-safe bounded summary handling;
* correct summary-before-retained-tail ordering;
* correct request accounting and trace lifecycle;
* comprehensive runtime tests;
* cleanup of the obsolete WIP branch after merge.

## Explicitly out of scope

Do **not** implement in this slice:

* a second provider request to generate a semantic summary;
* repeated overflow-recovery loops;
* automatic model failover for context overflow;
* dynamic provider context-window probing;
* changes to general context-profile thresholds;
* new user-facing configuration knobs for overflow recovery;
* new checkpoint behavior;
* speculative compression of the current turn;
* resurrection of WIP-specific machinery such as:

  * `overflow_seen`;
  * `provider_crossed`;
  * `maintenance_candidate`;
  * `turn_question`;
  * `summarize_oldest()`;
  * summary stand-in scanning;
  * provider-backed maintenance requests;
  * `TurnError::Exhausted`, unless independently justified by the new design.

Provider-generated summarization can be considered separately after the basic recovery behavior is stable.

# 3. Required invariants

These are non-negotiable implementation constraints.

## 3.1 Never replay committed provider output

A failed request is recoverable only when **nothing from that request has committed**.

Committed means any of:

* reasoning delta;
* assistant text delta;
* decoded tool call.

If any such output was committed, `ContextOverflow` is terminal for the turn.

Do not compact and replay the request.

---

## 3.2 Recover at most once per user turn

Automatic overflow recovery is a one-shot emergency mechanism.

Each invocation of `run_turn` / `run_turn_with_external_context` should hold local state similar to:

```rust
let mut overflow_recovery_used = false;
```

After a successful compaction attempt:

```rust
overflow_recovery_used = true;
```

A second provider-reported `ContextOverflow` during the same user turn must terminate the turn normally.

This state must **not** live on the long-lived `TurnLoop`.

---

## 3.3 Preserve the entire current turn verbatim

At the start of a user turn, record the boundary between prior session history and context introduced by this turn.

Conceptually:

```rust
let turn_history_start = self.messages.len();
```

This must happen before adding:

* external context;
* the user's new message;
* assistant tool-call messages;
* tool results;
* any other content produced during the turn.

Overflow recovery may compact only:

```text
messages[..turn_history_start]
```

Everything in:

```text
messages[turn_history_start..]
```

must remain in the same order and with the same content.

This is stronger and safer than preserving only the user's latest question.

---

## 3.4 Provider overflow is stronger evidence than the estimator

Do not route a provider-reported overflow back through ordinary context-threshold policy and ask whether the profile thinks compaction is necessary.

The provider has already established:

> The exact request sent did not fit.

Threshold policy is for proactive prevention.

Provider overflow recovery is reactive failure handling.

---

## 3.5 Request spans must always close correctly

A request that reaches the provider must preserve the normal request lifecycle regardless of whether recovery is attempted afterward.

The trace must still contain the equivalent of:

```text
ModelRequestStarted
...
ModelRequestCompleted
```

plus appropriate failure diagnostics.

Do not early-return from provider failure handling before request cleanup occurs.

---

## 3.6 Request budgets remain per-turn

Preserve the existing per-turn reset:

```rust
self.requests.store(0, Ordering::SeqCst);
```

Overflow recovery must not create state that leaks request counts across turns.

Because the initial implementation does not make a separate provider call for summarization, the expected successful recovery cost is:

```text
request 1: provider refuses with ContextOverflow
request 2: compacted reissue succeeds
```

---

## 3.7 Summary precedes retained history

Compacted context must have chronological semantics:

```text
[summary of older context]
[retained newer context]
[current-turn context]
```

Never:

```text
[retained newer context]
[summary of older context]
```

Correct the underlying compaction primitive if necessary.

---

## 3.8 All text bounding must be UTF-8 safe

Never truncate a Rust `String` using arbitrary byte indexes such as:

```rust
&text[..budget]
```

unless the boundary has first been verified with `is_char_boundary`.

Prefer a dedicated helper, for example:

```rust
fn truncate_utf8_to_bytes(text: &str, max_bytes: usize) -> &str
```

that backs down to the previous valid character boundary.

Tests must include Korean, Japanese, and emoji.

# 5. Recommended implementation slices

Implement the change in small, independently reviewable commits.

## Slice A — make model request assembly pure

### Goal

Separate:

1. context-policy mutation;
2. final `ModelRequest` construction.

Currently `build_request()` both evaluates policy and constructs the request.

Introduce a helper conceptually similar to:

```rust
fn assemble_request(&self, messages: Vec<Message>) -> ModelRequest
```

It must use exactly the same production settings as a normal model request:

* active model;
* active provider capabilities;
* system prompt;
* exposed tools;
* thinking level;
* message ordering.

Example conceptual structure:

```rust
fn assemble_request(&self, messages: Vec<Message>) -> ModelRequest {
  let capabilities = self.provider().capabilities();

  let tools = if capabilities.tools {
    self.tools.specs()
  } else {
    Vec::new()
  };

  let mut request =
    ModelRequest::new(self.active_model(), capabilities, messages)
      .with_tools(tools)
      .with_thinking(self.thinking);

  if let Some(system) = self.system.clone() {
    request = request.with_system(system);
  }

  request
}
```

Then `build_request()` performs policy handling and ends with:

```rust
Ok(self.assemble_request(self.messages.clone()))
```

### Why this is required

Overflow recovery must evaluate the same request shape that will actually be sent.

Do not duplicate estimation logic for:

* tools;
* system prompts;
* capabilities;
* reasoning settings.

### Tests

Add or adapt a test proving that `assemble_request()` includes:

* system prompt;
* tool specifications when supported;
* thinking level;
* messages in original order.

# 6. Slice B — introduce prefix-aware compaction

## Goal

Create a compaction primitive capable of replacing exactly an old prefix while leaving the remaining messages untouched.

Suggested conceptual API:

```rust
fn compact_prefix(
  &mut self,
  turn_id: &TurnId,
  prefix_end: usize,
  summary: &str,
) -> Result<u32, TurnError>
```

Given:

```text
[A, B, C, D, E]
```

and:

```text
prefix_end = 3
```

produce:

```text
[summary(A, B, C), D, E]
```

### Required behavior

The function must:

* reject or no-op for `prefix_end == 0`;
* clamp or reject values greater than `messages.len()`;
* record the existing durable compaction lifecycle;
* persist the summary before deleting replaced live context;
* increment `context_epoch`;
* set `last_compaction`;
* preserve the untouched suffix exactly;
* put the summary before retained newer history;
* return the number of messages replaced.

### Existing API compatibility

Do not unnecessarily break `/compact` or L2 compaction.

Prefer implementing shared internal machinery such as:

```rust
fn compact_range_or_prefix(...)
```

and preserving existing public interfaces around it.

### Tests

Test:

```text
[m1, m2, m3, m4]
```

compact first two →

```text
[summary, m3, m4]
```

Assert:

* `m3` unchanged;
* `m4` unchanged;
* summary is index `0`;
* event ordering remains correct;
* context epoch increments exactly once.

# 7. Slice C — make summary generation safely bounded

The first overflow-recovery implementation should use the existing local/structured summarizer.

Do not make another provider request.

## Summary source

Use either:

```rust
structured_summary(prefix)
```

or the configured synchronous summarizer hook if its semantics are appropriate.

Prefer a small helper:

```rust
fn summarize_prefix_for_overflow(
  &self,
  messages: &[Message],
  budget_tokens: u64,
) -> String
```

The output must be bounded.

## Conservative summary budget

Do not assume the full context window is available to the summary.

Determine available space from the actual retained request.

Conceptually:

```text
window
- current-turn suffix
- retained recent history
- system prompt
- tools
- normal request overhead
- safety margin
= maximum summary allowance
```

Because token estimation is approximate, leave explicit headroom.

A simple initial rule is acceptable, for example:

```text
candidate must estimate <= 90-95% of advertised context window
```

or:

```text
candidate <= window - fixed/minimum safety reserve
```

The exact safety function should be centralized and documented.

Avoid WIP-style independent `request_reserve() = 1` approximations.

# 8. Slice D — introduce provider-overflow as a distinct internal outcome

Current failure routing should distinguish:

* provider returned `ContextOverflow`;
* runtime proactively refused to build/send;
* ordinary provider failure.

Introduce an internal state conceptually like:

```rust
enum TurnFailure {
  Cancelled,
  ProviderOverflow(ModelFailure),
  Fatal(ModelFailure),
  Sink(SinkError),
}
```

The exact name can differ.

## In `attempt()`

When the provider returns:

```rust
ModelFailureKind::ContextOverflow
```

first perform the same request-finalization work as every other provider failure.

Specifically:

1. propagate whether content committed;
2. fill attempt/model metadata;
3. emit `ModelRequestCompleted`;
4. close decoded-but-unexecuted calls appropriately;
5. emit diagnostics;
6. check cancellation;
7. only then classify the result.

Then:

```text
ContextOverflow + committed == false
    → ProviderOverflow(failure)

ContextOverflow + committed == true
    → Fatal(failure)
```

Do not pass provider overflow through failover policy.

`failover.rs` should continue treating context overflow as non-failoverable.

# 9. Slice E — implement one-shot overflow recovery in the outer turn loop

At the beginning of:

```rust
run_turn_with_external_context(...)
```

retain existing request-budget reset.

Then capture:

```rust
let turn_history_start = self.messages.len();
let mut overflow_recovery_used = false;
```

Add external context and the user message normally.

## Recovery arm

Conceptually:

```rust
match self.attempt(...) {
  Ok(response) => { ... }

  Err(TurnFailure::ProviderOverflow(failure)) => {
    if overflow_recovery_used {
      return terminal_overflow(...);
    }

    if turn_history_start == 0 {
      return terminal_overflow(...);
    }

    let recovered = self.recover_context_overflow(
      &turn_id,
      turn_history_start,
      ...
    )?;

    if !recovered {
      return terminal_overflow(...);
    }

    overflow_recovery_used = true;
    continue;
  }

  ...
}
```

The real implementation must use the existing turn-finalization conventions rather than literally returning as above.

---

# 10. `recover_context_overflow()` design

Introduce one focused helper.

Suggested responsibility:

```rust
fn recover_context_overflow(
  &mut self,
  turn_id: &TurnId,
  turn_history_start: usize,
) -> Result<bool, TurnError>
```

## Algorithm

### Step 1 — verify compactable prior history exists

If:

```rust
turn_history_start == 0
```

return:

```rust
Ok(false)
```

The current turn itself must never be summarized away.

---

### Step 2 — snapshot the current-turn suffix

Conceptually:

```rust
let current_turn = self.messages[turn_history_start..].to_vec();
```

This is used for candidate construction and tests.

Do not mutate it.

---

### Step 3 — find an appropriate amount of pre-turn history to replace

Start aggressively.

A provider has already proved the prior request was too large, so this recovery does not need to optimize for minimal compression.

Prefer:

* compact the whole pre-turn prefix first; or
* retain only a small recent tail of the pre-turn history if existing compaction semantics require it.

The simplest robust initial behavior is:

```text
all pre-turn history → one summary
current-turn suffix → untouched
```

This maximizes recovery probability and minimizes candidate-search complexity.

Future work can optimize retention.

---

### Step 4 — create a candidate without mutating live history

Build:

```text
[summary candidate]
[current-turn suffix]
```

through the same exact request assembler used by the production request path.

Do not call `build_request()` as a probe.

`build_request()` may perform policy-driven mutations and therefore must never be used merely to inspect size.

---

### Step 5 — validate fit

Use:

```rust
estimate_tokens(&candidate)
```

against a conservative effective limit.

Example:

```rust
candidate_tokens <= overflow_recovery_target(window)
```

where `overflow_recovery_target()` leaves explicit headroom.

If the candidate does not fit:

1. shorten the summary safely;
2. rebuild the exact candidate;
3. retry locally a bounded number of times.

Do **not** mutate actual history until a candidate has been accepted.

If no candidate fits:

```rust
return Ok(false);
```

---

### Step 6 — commit compaction durably

Once a fitting candidate is found:

```rust
self.compact_prefix(
  turn_id,
  turn_history_start,
  &summary,
)?;
```

Verify/debug-assert that:

```text
self.messages[1..] == previous current-turn suffix
```

when the compacted prefix was non-empty.

---

### Step 7 — return

```rust
Ok(true)
```

The normal outer loop will build and send the actual request again.

Do not store a special `maintenance_candidate` request.

The normal production path should construct the reissue from the newly compacted canonical model-visible state.

---

# 11. Why not cache the candidate request?

The WIP introduced `maintenance_candidate`.

Do not replicate it unless profiling or correctness forces it.

After compaction, normal `build_request()` should see the updated model-visible history.

That keeps one canonical request-construction path and avoids divergence between:

```text
request measured during recovery
```

and:

```text
request actually sent
```

If context policy tries to compact again immediately after emergency recovery, handle that explicitly with policy state/cooldown rather than bypassing the normal builder with a cached request.

---

# 12. Context policy interaction

Provider overflow recovery should not depend on:

```rust
ContextState::overflow_observed
```

for the current turn's emergency handling.

That field can remain for other policy use if already part of the public contract.

Do not add sticky `TurnLoop` state solely to set it.

If the existing field becomes unused in production after this change, leave its cleanup for a separate focused slice unless removal is trivial and clearly safe.

---

# 13. Terminal overflow behavior

A terminal provider overflow should:

* preserve the original provider failure kind;
* finalize the request span;
* finalize the turn;
* emit the expected diagnostics;
* return an error with:

```rust
ModelFailureKind::ContextOverflow
```

Terminal cases include:

* provider emitted content before overflow;
* no pre-turn history exists;
* compaction candidate cannot fit;
* compaction itself fails;
* second overflow in the same turn.

Do not convert these into:

* transport failures;
* authentication failures;
* failover;
* successful completed turns.

# 15. Event and trace expectations

For a successful recovery, the trace should conceptually resemble:

```text
user_message
model_request_started
model_request_completed        # refused overflow
diagnostic                     # provider overflow
context_compaction_started
context_summary
context_compaction_epoch
context_compaction_completed
model_request_started          # reissue
assistant_delta...
model_request_completed
turn_completed
```

Exact ordering of diagnostics may follow existing conventions.

Critical requirements:

* no dangling `ModelRequestStarted`;
* no duplicate turn completion;
* one compaction epoch only;
* no `model_failover`;
* canonical pre-compaction history remains recoverable from trace/store.

# 23. Definition of done

The slice is complete when a long-running session can encounter a provider-side context-window refusal and, without replaying committed work or damaging the current turn, automatically condense only older history, retry exactly once, and either continue normally or fail explicitly.

The implementation should leave fewer special cases in the runtime than the abandoned WIP branch, not more.

The guiding principle is:

> **Use proactive policy to avoid overflow; use one bounded, auditable recovery when the provider proves the estimate was wrong.**
